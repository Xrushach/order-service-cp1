# Сервис заказов

Учебный REST API на Go. Данные хранятся в памяти и теряются после перезапуска приложения.

## Запуск

Требуется Go 1.22 или выше. Команды выполняются из корня проекта, где находится `go.mod`:

```bash
go mod download
go run ./cmd/api
```

По умолчанию сервер работает по адресу `http://localhost:8080`.

Порт можно изменить через переменную `HTTP_ADDR`

```bash
HTTP_ADDR=:8081 go run ./cmd/api
```

## API

| Метод | Путь | Назначение |
| :--- | :--- | :--- |
| `GET` | `/health` | Проверка доступности |
| `POST` | `/api/v1/orders` | Создание заказа |
| `GET` | `/api/v1/orders` | Список заказов |
| `GET` | `/api/v1/orders/{id}` | Получение заказа |
| `PATCH` | `/api/v1/orders/{id}/status` | Изменение статуса |
| `GET` | `/api/v1/orders/{id}/history` | История статусов |

Пример тела запроса для создания заказа:

```json
{
  "items": [
    {
      "name": "Kola",
      "quantity": 10,
      "price": 150
    }
  ]
}
```

Успешный ответ имеет код `201`.

Цена задаётся целым числом в копейках. Название товара не должно быть пустым, количество и цена должны быть положительными. Заказ должен содержать хотя бы одну позицию. Новый заказ получает статус `new`.

Допустимые переходы статусов:
- `new` → `processing`
- `new` → `cancelled`
- `processing` → `completed`
- `processing` → `cancelled`

Статусы `completed` и `cancelled` являются конечными.

Пример тела для изменения статуса:

```json
{
  "status": "processing"
}
```

## Ошибки

- `400` — Некорректный JSON, данные, ID или неизвестный статус
- `404` — Заказ не найден
- `409` — Запрещённый переход статуса
- `500` — Внутренняя ошибка

Единый формат ответа с ошибкой:

```json
{
  "error": "order not found",
  "code": "NOT_FOUND"
}
```

## Архитектура

- `cmd/api` — создание зависимостей и запуск сервера
- `internal/order` — модели, ошибки и интерфейс репозитория
- `internal/handler` — HTTP-маршруты, middleware и обработка ошибок
- `internal/service` — валидация, расчёт стоимости, статусы и история
- `internal/repository/memory` — хранение заказов в памяти

Каждый запрос логируется через `slog` с полями `method`, `path`, `status`, `duration` и `req_id`. Идентификатор запроса также возвращается в заголовке `X-Request-ID`.

Recovery перехватывает панику, пишет в лог и возвращает JSON-ответ с кодом `500`.
